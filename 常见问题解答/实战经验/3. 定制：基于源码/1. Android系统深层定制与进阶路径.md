# Android 系统深层定制与进阶开发指南

对于 Android 平台/系统开发而言，修改 XML 配置文件或添加资源 Overlay 仅仅属于“系统配置与定制”的初级阶段。若要深入 Android 系统底层，实现软硬件垂直整合，需向 Framework 系统服务、HAL（硬件抽象层）、SELinux 安全策略以及 Linux 内核驱动进军。

本指南为您梳理了 Android 系统深层定制的五大核心阶段及技术路径，供后续学习、Review 和完善。

---

## 一、 系统定制的五大核心阶段

### 阶段 1：SystemUI 与 Framework 机制定制（系统业务层）
系统定制最直接的体现是用户界面和交互规则的修改。这要求掌握 Framework 的内部核心逻辑。
*   **1. 深度定制 SystemUI**：
    *   *实战任务*：定制系统状态栏（StatusBar）、导航栏（NavigationBar）、锁屏界面以及下拉快捷面板（Quick Settings）。
    *   *学习重点*：SystemUI 模块的生命周期、Dagger 依赖注入、系统状态（如电池、信号、Wi-Fi）的广播监听与动态渲染。
*   **2. 定制核心系统服务（AMS / WMS / PMS）**：
    *   *实战任务*：
        *   **PMS（Package Manager Service）**：实现应用防卸载白名单、静默安装特定应用、阻止未授权应用的安装。
        *   **AMS（Activity Manager Service）**：定制多任务（Recents）的切换与过滤规则、多窗口/分屏（Split-screen）的窗口边界限制。
        *   **WMS（Window Manager Service）**：定制悬浮窗的层级控制、全面屏手势的拦截与交互反馈逻辑。
    *   *学习重点*：掌握系统服务跨进程通信（IPC）的底层实现，通过修改 `frameworks/base/services/core/java/com/android/server/` 下的源码来拦截并更改系统行为。

---

### 阶段 2：增加自定义 System Service（系统承上启下）
当需要为特定硬件产品设计特有功能（如定时开关机、物理主板控制）并暴露接口供应用层 App 调用时，必须在 Framework 中创建自定义的系统服务。
*   **核心开发工作流**：
    1.  **定义 AIDL 接口**：声明 App 与系统进程进行 Binder 跨进程通信的接口契约（如 `IFireflyManager.aidl`）。
    2.  **实现 Service 服务类**：在 Framework 中编写具体的 Java 业务逻辑实现（如 `FireflyService.java`）。
    3.  **系统服务注册**：将其注册到系统核心管理类 `SystemServer.java` 中，使其随系统开机自动拉起并发布到 `ServiceManager`。
    4.  **提供 SDK 接口**：将服务包装为代理 Manager，并通过编译生成自定义 SDK jar 包，供上层 App 依赖和调用。

---

### 阶段 3：HAL（硬件抽象层）与 JNI 开发（软硬件互通）
Android 通过 HAL（硬件抽象层）隔离了上层应用与底层的 Linux 内核驱动。在定制专有硬件设备时，这是最核心的链路。
*   **实战任务**：从应用层 App 发送指令，控制开发板上的物理外设（如控制 LED 闪烁、读取 GPIO 状态、控制温控风扇）。
*   **软硬件互通的五层架构模型**：
    1.  **Driver（驱动层）**：在 Linux 内核中编写硬件驱动，生成设备节点（如 `/dev/my_led`）。
    2.  **HAL（硬件抽象层）**：使用 C++ 编写 HAL 模块（在 Android 8+ 后推荐使用 **HIDL** 或 **AIDL** 绑定的 Binder 化 HAL），读取并写入底层驱动节点。
    3.  **JNI（本地接口层）**：编写 C++ JNI 绑定代码，提供 Java 访问 C++ HAL 的通道。
    4.  **Framework Service（系统服务）**：用 Java 封装系统级服务（如 `LedService`），暴露控制接口。
    5.  **App（应用层）**：通过 `getSystemService("led")` 调用系统接口，完成物理控制。

---

### 阶段 4：SELinux 安全策略适配（系统安全限制）
在现代 Android 安全体系中，任何新增的硬件节点、自定义进程或自定义系统服务，都会受到 **SELinux（Security-Enhanced Linux）** 强制访问控制机制的拦截，表现为权限不足（Permission denied）。
*   **实战任务**：为新增的自定义系统服务和 `/dev/` 物理节点配置正确的访问权限规则。
*   **学习重点**：
    *   通过 `dmesg | grep denied` 或 `logcat -b events` 捕获并阅读 SELinux 拒绝日志。
    *   在 `device/rockchip/common/sepolicy/` 等板级目录下编写并配置 `.te`（Type Enforcement）安全策略文件（如声明设备标签、授权 system_server 拥有对该字符设备的读写权限）。

---

### 阶段 5：Linux 内核驱动与设备树（DTS）开发（硬件最底层）
对于涉及定制主板、焊接新外设传感器等硬件的项目，需要深入到 Linux 内核级别。
*   **设备树（Device Tree, DTS/DTSI）**：
    *   *学习重点*：了解芯片引脚复用（I2C, SPI, GPIO 等），在 `kernel/arch/arm64/boot/dts/rockchip/` 目录下修改板级设备树文件，声明外设的引脚属性、硬件中断（IRQ）和电源供应（Regulator）。
*   **内核驱动程序开发**：
    *   *学习重点*：使用 C 语言编写 Linux 字符设备或平台设备（Platform Device）驱动，注册硬件控制接口、处理物理中断以及编写电源管理唤醒逻辑。

---

## 二、 进阶开发切入点建议（从哪里开始）

建议按照 **“由上至下”** 或 **“从中间打通”** 的方式开始实战：

1.  **推荐入门项目 A：定制 AMS 拦截应用启动**
    *   *目标*：在 Framework 中修改 AMS 启动逻辑，实现当启动特定非白名单应用时，系统自动拦截并弹出自定义的警告框。
    *   *作用*：快速熟悉 Framework 核心代码架构、Binder 通信以及模块化编译部署。
2.  **推荐入门项目 B：板载外设控制（垂直打通）**
    *   *目标*：实现 App 改变物理开发板上 LED 灯的状态。
    *   *作用*：完整走通一整条从 “App $\to$ Framework Service $\to$ JNI $\to$ HAL $\to$ Kernel Driver” 的 Android 经典全栈链路。
