# 瑞芯微 Android 10.0 编译与刷机深度回测

这是一份用于巩固和复习 Android 10.0 开发中关于固件烧录、编译预装、Conda 隔离和环境踩坑的自测集。

---

## 📝 填空题

### 📌 第一部分：引导程序与名词解释 (U-Boot)
1. **U-Boot** 扮演的角色就相当于普通电脑主板上的 **`(  ①  )`** 或 **`(  ②  )`**。它是系统上电后运行的第一段软件代码。
2. U-Boot 刚通电时的三大核心任务是：
   * **`(  ③  )`**（若更换了内存颗粒或改了时钟频率，就必须修改 U-Boot 源码并重新编译它）。
   * **`(  ④  )`**（负责将存储在 eMMC 或 SD 卡中的内核加载到 RAM 中，并把控制权交给内核，从而真正拉起启动 Android）。
   * **`(  ⑤  )`**（支持长按按键进入特定的 Loader 或 MaskROM 等模式，允许通过 USB 重新烧录固件）。

### 📌 第二部分：源码下载、合并与 Git 补丁管理
3. Android 10 源码为了方便大文件传输，采用 **`(  ⑥  )`** 机制分包存储。其中，后缀为 `.7z.001 ~ .005` 的是分卷基础包，只需使用 `7z` 命令解压 **`(  ⑦  )`** 即可。
4. 源码中名为 `rk3399-android10.0-bundle` 的文件夹存放的是官方的 **`(  ⑧  )`** 补丁包。
5. 合并补丁包时，需要先使用命令 `ln -s ... .bundle` 将补丁目录软链接为源码根目录下的 **`(  ⑨  )`** 隐藏文件夹；然后再运行 **`(  ⑩  )`** 脚本进行合并；最后执行命令 **`(  ⑪  )`** 应用所有最新的代码。

### 📌 第三部分：Conda 虚拟环境隔离与管理
6. 编译 Android 10 固件依赖 **`(  ⑫  )`** 版本的 Python 环境，而现代的 Ubuntu 24.04 默认系统版本是 3.13。我们可以使用 Conda 虚拟环境创建并激活该版本，对应的命令是：
   * 创建环境：`conda (  ⑬  ) python2 python=2.7`
   * 激活环境：`conda (  ⑭  ) python2`
7. 在使用 Conda 时，若要查看当前系统中**已有的所有虚拟环境**，可以使用命令 **`conda (  ⑮  )`** 或 **`conda (  ⑯  )`**。

### 📌 第四部分：全量编译准备与固件打包
8. 运行整体编译命令 `./FFTools/make.sh -d rk3399-roc-pc-plus -j8 -l rk3399_roc_pc_plus-userdebug` 中：
   * 参数 `-d` 后面指定的 `rk3399-roc-pc-plus` 用于确定设备的 **`(  ⑰  )`** 和硬件板级配置。
   * 参数 `-j8` 表示 **`(  ⑱  )`**。
   * `userdebug` 则代表编译出来的 Android 系统 **`(  ⑲  )`**。
9. 编译完成各个分区分卷后，需要通过执行打包命令 **`(  ⑳  )`** 才能生成用于 `upgrade_tool` 烧录的 `update.img` 统一固件包。

### 📌 第五部分：刷机状态、指令与全局工具避坑
10. 在 Android 10 环境下，必须使用 **`(   there are ㉑  )`** 及以上版本的 `upgrade_tool`，否则会引发 `Download Firmware Fail` 报错。
11. 通过 `sudo` 执行当前普通用户主目录下的二进制文件时，会因为 `root` 用户无法跨越访问 `/home/wangwu/` 目录而报 `command not found` 错误。此时应当将工具和配置文件临时挪到 **`(  ㉒  )`** 目录中转，然后成功复制到系统全局目录 **`(  ㉓  )`** 中，并使用 `chown root:root` 和 `chmod a+x` 授予执行权。
12. 当 `adb devices` 显示为 `recovery` 状态时，必须运行 **`(  ㉔  )`** 命令才能进入烧录模式。
13. 清除 Flash 全盘数据的命令是 `sudo upgrade_tool (  ㉕  ) <img_path>`。执行该擦除后，由于 Flash 中没有有效引导代码，设备重新通电时指示灯闪一下就灭，这是芯片自动回退到硬编码在 CPU 内部的 **`(  ㉖  )`** 模式的正常表现。
14. 在 Loader 模式下，若是日常同系统升级的开发场景，直接使用 **`(  ㉗  )`** 命令烧录固件是完全可行且首选的方法。

### 📌 第六部分：应用预置与 Makefile 依赖安全
15. 想要将 APK 预装为 **用户可卸载（且恢复出厂设置后会自动还原）** 的应用，需将其放入编译目录 **`(  ㉘  )`** 下；若想作为 **系统级应用（不可卸载）**，则需放入 **`(  ㉙  )`** 下。
16. APK 命名必须避坑，绝对不能包含 **`(  ㉚  )`** 和 **`(  ㉛  )`**。
17. 在预装目录中只删除 `.apk` 是安全的，但如果误删了文件夹本身或其中的 **`(  ㉜  )`** 配置文件，会导致整个 SDK 编译崩溃中断。
