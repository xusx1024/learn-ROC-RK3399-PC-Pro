# ROC-RK3399-PC-Pro Android 10 开发典型名词解释速查手册

在进行 Rockchip 平台的 Android 10 底层驱动、内核以及系统 Framework 开发定制时，理解以下核心概念能够帮助您快速理清系统架构与编译打包的底层机理。

---

### 1. U-Boot (Universal Boot Loader)
*   **基本定义**：类似于普通 PC 电脑上的 BIOS/UEFI，是开发板通电后最先运行的、高度通用的嵌入式**“引导程序”**代码。
*   **核心作用**：负责在极度受限的环境中初始化最基础的硬件设施（如 CPU 核心、DDR 内存、系统时钟等），接着将存放在非易失性存储器（如 eMMC、SD 卡）中的 Linux/Android 操作系统内核（Kernel）与设备树（DTB）加载到内存中并启动它们。此外，U-Boot 还提供了用于固件底层烧录与救砖的特殊模式（如 Rockchip Loader 模式、Fastboot 模式等）。

---

### 2. Soong (Android 10+ 核心编译构建系统)
*   **基本定义**：Google 从 Android 7.0 (Nougat) 开始引入，在 Android 10 中确立完全统治地位的**下一代全新声明式编译系统**，用于全面替代传统臃肿的 GNU Make 编译体系。
*   **核心特性**：
    *   **构建脚本定义**：Soong 不再解析传统的 `Android.mk`，而是解析采用声明式、类似 JSON 的 **`Android.bp`（Blueprint）** 构建配置文件。
    *   **依赖树缓存**：Soong 内部基于严格的依赖关系图（Dependency Graph）进行极速增量构建，其编译的所有中间产物均会被高度优化并缓存在 `out/soong/.intermediates/` 目录下。
*   **实战开发避坑点**：
    在对系统 Framework 资源（如 `framework-res`）进行 Overlay 无损替换或定制开发时，由于 Soong 强大的缓存惰性，仅使用传统的 `rm -rf out/target/common/obj/APPS/..._intermediates`（旧版 Make 缓存）是**绝对无法**触发重新编译的！必须手动清理其对应的 Soong 缓存：
    `rm -rf out/soong/.intermediates/frameworks/base/core/res/framework-res/`，方能强行让编译器重新捕获 Overlay 改动。

---

### 3. RRO (Runtime Resource Overlay) 运行时资源覆盖
*   **基本定义**：Android 系统级的一项卓越技术。它允许我们在**完全不重新编译或修改目标应用（如系统框架、系统 UI、核心设置等）APK 本身**的前提下，在系统运行时，将一个独立的、仅包含资源的“皮肤包”APK（即 Overlay APK）中的自定义资源，动态地重定向并合并替换至目标应用中。
*   **核心优势**：
    *   **代码零侵入**：目标 App 业务代码无需做任何适配与修改。
    *   **功能极其强大**：不仅能替换图片、颜色、字符串，甚至还能直接替换整套布局（Layout XML 文件）。
    *   **性能零损耗**：由系统级资源加载器（`AssetManager`）在底层通过重定向表格映射实现，性能等同于原生资源加载，且完全由官方系统服务（OMS）安全管控。

---

### 4. Enforce RRO (强制运行时资源覆盖)
*   **基本定义**：从 Android 9/10 开始，Google 为了彻底推行 **Project Treble（将 Google 核心系统源码与芯片厂商 SoC、OEM 厂商的定制实现进行物理和架构级完全解耦）**，引入的强制性资源覆盖隔离规则。
*   **编译构建表现**：一旦产品 Makefile 中配置启用了 `PRODUCT_ENFORCE_RRO_TARGETS := framework-res`，编译器在打包时如果发现任何针对 `framework-res` 的静态覆盖目录（即 `PRODUCT_PACKAGE_OVERLAYS` 或 `DEVICE_PACKAGE_OVERLAYS` 中的定制壁纸或 `config.xml` 覆盖），**会自动强行拦截，绝不允许它们被编译进基础的 `framework-res.apk` 中**！
*   **资源最终去向**：
    编译器在后台会自动剥离这些 Overlay 覆盖，并动态生成一个独立的 RRO 插件包 APK（例如 `framework-res__auto_generated_rro_product.apk`），并将其直接打包输出至 `product` 或 `vendor` 的 `/overlay` 文件夹下。在系统运行时，再由 AssetManager 动态合并。
    **这正是修改默认壁纸后，直接解包主框架包 `framework-res.apk` 会发现“里面的图片依然是 Google 默认原图且大小没变”的底层架构原因！**
