## 定制Launcher（桌面系统）

最核心、最常见的开发任务

### 路线一：修改系统自带的 Launcher3（原生深度定制）
主要定制点包括：

1. 更改默认壁纸：更换成公司品牌的静态/动态默认壁纸。
   
   **【实战操作】推荐使用“资源覆盖（Resource Overlay）”机制进行无损定制：**
   * **原理**：Android 的默认壁纸由系统核心框架（Framework Resources）管理。不推荐直接修改 `/frameworks/base/` 源码，而是利用 Rockchip 的 overlay 机制，让编译器在打包时自动替换默认壁纸。

   * **深入剖析：为什么 Overlay（资源覆盖）机制可以起作用？**
     * **运行机制**：在产品的 Makefiles（例如 `device/rockchip/rk3399/device.mk`）中，配置了 `DEVICE_PACKAGE_OVERLAYS += device/rockchip/rk3399/overlay`。在编译打包阶段，Android 资源打包工具（AAPT）会优先检索该 overlay 目录。如果发现该目录下有与系统 AOSP 基础包（如 `frameworks/base/core/res/`）**完全一致的相对路径和文件名**的文件，它就会用这个文件**直接覆盖掉**系统默认资源，实现了“零入侵”定制，极便于 SDK 版本升级。

   * **关于分辨率适配与屏幕检测：**
     * **第一步：查看当前连接屏幕 of 物理分辨率（ADB 指令）**：
       在开发板正常开机并连接屏幕后，可以在电脑终端通过 ADB 指令快速检测屏幕的实际物理属性：
       ```bash
       # 1. 查看屏幕物理分辨率（例如输出：Physical size: 1920x1080）
       adb shell wm size
       
       # 2. 查看屏幕像素密度/DPI（例如输出：Physical density: 240）
       adb shell wm density
       ```
     * **第二步：屏幕分辨率适配与 `nodpi` 避坑**：
       * **`sw600dp` 与 `sw720dp` (最小宽度适配)**：`sw` 代表 Smallest Width（最小宽度）。当系统检测到外接屏幕的最小宽度达到 600dp（如 7 寸平板）或 720dp（如 10 寸大屏/HDMI 显示器）时，会优先去加载对应的 `drawable-swXXXdp-nodpi` 文件夹下的壁纸，从而防止单张壁纸拉伸变形。
       * **为什么一定要把壁纸放在 `nodpi` 目录？**
         `nodpi` 意为 **“无密度缩放（No Density Scaling）”**。如果把壁纸放在 `hdpi`、`xhdpi` 等文件夹下，Android 的资源管理器会根据屏幕的实际 DPI 对壁纸进行强行像素缩放（插值拉伸或压缩），这极易导致**壁纸边缘模糊**，更严重的是会触发 **内存爆涨（Out Of Memory, OOM）** 导致开机卡动画或 Launcher 崩溃。放在 `nodpi` 下，图片会以 1:1 的原始物理像素进行渲染，内存占用最低且最清晰。
       * **项目支持的常见屏幕分辨率参考（根据官方屏幕模组文档）**：
         * 7寸 LVDS 屏：`800x1280` (竖屏)
         * 10.1寸 MIPI 屏：`1200x1920` (竖屏)
         * HDMI 显示器：`1920x1080` (主流) / `3840x2160` (HDMI 4K UI拉伸模式)

   * **操作步骤**：
     1. 准备一张 `.png` 格式 of 壁纸，建议分辨率与屏幕一致（如 1920x1080），命名为 `default_wallpaper.png`。
     2. 在 SDK 目录中创建对应的 overlay 资源目录（按分辨率和屏幕宽度匹配）：
        ```bash
        # 创建默认覆盖目录
        mkdir -p device/rockchip/rk3399/overlay/frameworks/base/core/res/res/drawable-nodpi/
        # 创建大屏/平板匹配覆盖目录（防拉伸）
        mkdir -p device/rockchip/rk3399/overlay/frameworks/base/core/res/res/drawable-sw600dp-nodpi/
        mkdir -p device/rockchip/rk3399/overlay/frameworks/base/core/res/res/drawable-sw720dp-nodpi/
        ```
     3. 将您的 `default_wallpaper.png` 分别拷贝并替换到上述三个创建好的 `drawable-...-nodpi/` 目录中。
     4. 重新全量编译 Android 并打包统一固件 `update.img`：
        ```bash
        ./FFTools/make.sh -d rk3399-roc-pc-plus -j8 -l rk3399_roc_pc_plus-userdebug
        ./FFTools/mkupdate/mkupdate.sh -l rk3399_roc_pc_plus-userdebug
        ```

2. 定制默认桌面布局（图标/快捷方式）：

    - 在桌面预置常用 App 的图标位置（例如让 Chrome、Settings 或者您的自定义预装 App 默认出现在桌面上）。
    - 移除或保留底部的快捷栏（Hotseat）图标。
    - 修改对应的配置文件：/packages/apps/Launcher3/res/xml/default_workspace_5x5.xml。

   * **原理**：Launcher3 的默认布局由 XML 配置文件决定。在您的 SDK 中，主要的网格配置文件为 `/packages/apps/Launcher3/res/xml/default_workspace_5x5.xml`。
   * **操作步骤**：
     1. 打开 `default_workspace_5x5.xml` 配置文件。
     2. 若要预置自定义 App 的图标位置，在 xml 中添加 `<favorite>` 标签：
        ```xml
        <favorite
            launcher:screen="0"
            launcher:x="1"
            launcher:y="1"
            launcher:packageName="com.example.fireflydemo"
            launcher:className="com.example.fireflydemo.MainActivity" />
        ```
        *(其中 `screen` 表示第几屏，`x` 和 `y` 表示在 5x5 网格中的坐标，从 0 开始算起。)*
     3. 若要修改底部常驻快捷栏（Hotseat）图标，修改带有 `launcher:container="-101"` 的节点。

3. 隐藏或移除 Google 顶部搜索栏：对于无梯度的国内系统，默认的谷歌搜索栏通常无法使用且占用桌面空间，可以通过修改源码将其彻底隐去。
4. 修改图标网格大小：如把 5x5 网格改为 4x4 或 3x3。

### 路线二：使用第三方 Custom Launcher 替换原生桌面（专有设备定制）
如果您有自己开发好的专用 App（例如数字标牌展示系统、一体机交互界面、智能工控 App），希望设备一开机就直接进入您的 App 且不允许用户退出到普通桌面（即 Kiosk 亭屏模式）：

1. 屏蔽原生 Launcher3：在源码编译配置文件（device.mk）的 PRODUCT_PACKAGES 中，将 Launcher3 或 Launcher3QuickStep 模块剔除。
2. 预置您的主屏 App 为系统级应用：把您的自定义 Launcher 放入 preinstall/ 中，并确保其 AndroidManifest.xml 中配置了主屏过滤项：
```xml
<application
    android:label="@string/app_name"
    android:icon="@mipmap/ic_launcher">
    <activity
        android:name=".MainActivity"
        android:exported="true">
        <intent-filter>
            <!-- 核心！这告诉系统你的 App 是主屏幕/桌面 -->
            <category android:name="android.intent.category.HOME" />
            <!-- 如果要让它取代锁屏（可选） -->
            <category android:name="android.intent.category.DEFAULT" />
            <!-- 如果要支持长按电源键唤醒（可选） -->
            <category android:name="android.intent.category.LAUNCHER_APP" />
            <action android:name="android.intent.action.MAIN" />
        </intent-filter>
    </activity>
</application>
```
