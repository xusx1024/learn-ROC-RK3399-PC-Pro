直接使用干净的 SDK 源码编译打包出来的新固件，默认就不会包含预装App。

- 预装这些 App，且允许用户在系统内手动卸载（推荐）： 将下载好的 .apk 放置到如下目录（注意：文件名不要有中文或特殊字符）：/home/wangwu/firefly/3399-pro/rk3399_Android10.0/device/rockchip/rk3399/preinstall_del/
- 将这些 App 作为系统级应用，不允许用户卸载： 将下载好的 .apk 放置到如下目录：/home/wangwu/firefly/3399-pro/rk3399_Android10.0/device/rockchip/rk3399/preinstall/

| 文件夹名称 | 说明 | 适用场景|
| :-- | :-- | :-- |
| preinstall | 不可卸载（系统应用级） | 内部系统服务、公司核心业务软件、必须常驻的后台监控程序。|
| preinstall_del（最常用） | 可卸载（恢复出厂设置后可恢复） | 官方 Demo 软件、默认输入法、默认浏览器等出厂预装软件。|
|preinstall_del_forever|可卸载（彻底卸载，无法恢复）|出厂附赠的第三方推广软件或临时测试程序。|


文件名避坑（最重要）： APK 的文件名千万不要包含中文、空格或特殊字符。建议仅使用英文字母、数字和下划线，例如 MyTestApp.apk。

系统架构匹配： 确保您的 APK 能够支持 ARM 或 ARM64 架构（RK3399 是 64 位的 ARM 芯片，目前市面上 99% 的安卓 App 都支持）。

开机时间： 如果您在 preinstall_del 中放了非常多、体积非常巨大的 App，开发板在第一次开机（即刚刷完机）时，开机动画可能会停留得比平时稍久一点。这是因为系统在后台释放并安装这些 App，第二次开机就会恢复正常速度。

删除这些文件夹中的 .apk 文件是完全没有风险的，但绝对不要删除文件夹本身以及文件夹内的 .mk 配置文件。

如果您删除了文件夹本身，或者删除了里面的 Android.mk / preinstall.mk 文件：

后果：SDK 编译将会直接报错并中断。
原因：Android 系统的编译框架（Makefile）在启动时会通过 include 语法强制去读取这些 .mk 配置文件。如果找不到这些文件，编译器会抛出类似 cannot open '...preinstall.mk': No such file or directory 的致命错误，导致固件根本无法编译出来。

### 二、 如何彻底删除已预装的 App？

在开发调试或固件裁剪过程中，如果需要删除某些已经加入预装的 App，请遵循以下完整步骤，避免由于编译缓存或设备缓存导致删除失效。

#### 步骤 1：删除源码目录中的 APK 文件
直接进入对应的预装源码目录，删除该 `.apk` 文件。
*   **不可卸载（系统应用）**：进入 `device/rockchip/rk3399/preinstall/`，删除对应的 APK 文件（例如 `MyTestApp.apk`）。
*   **可卸载（用户应用）**：进入 `device/rockchip/rk3399/preinstall_del/` 或 `preinstall_del_forever/`，删除对应的 APK 文件。

> [!WARNING]
> **切记**：仅需删除对应的 `.apk` 文件。**绝对不要**删除 `preinstall/` / `preinstall_del/` 文件夹本身，以及文件夹内的 `Android.mk` 或 `preinstall.mk` 配置文件，否则会触发系统编译中断。

#### 步骤 2：彻底粉碎编译输出缓存（核心避坑点）
Android 编译系统在增量编译时，**只负责把新文件复制进 `out/` 目录，但不会自动从 `out/` 目录中删除已丢弃的文件**。如果不手动清理编译输出，重新打包后的固件依然会包含该预装应用。
1. 在源码根目录下，查找并删除 `out/` 目录中对应的编译输出文件夹（以 `MyTestApp` 为例）：
   ```bash
   # 如果是系统应用（preinstall）：
   rm -rf out/target/product/rk3399_roc_pc_plus/system/app/MyTestApp/
   rm -rf out/target/product/rk3399_roc_pc_plus/system/priv-app/MyTestApp/

   # 如果是可卸载应用（preinstall_del）：
   rm -rf out/target/product/rk3399_roc_pc_plus/oem/app/MyTestApp/
   ```
2. 为了保险起见，建议直接运行 `find` 确认输出目录中已无残留：
   ```bash
   find out/target/product/rk3399_roc_pc_plus/ -name "MyTestApp*"
   ```

#### 步骤 3：重新编译并打包固件
清理完缓存后，重新运行编译和打包脚本生成新的 `.img` 固件：
```bash
./FFTools/make.sh -d rk3399-roc-pc-plus -j8 -l rk3399_roc_pc_plus-userdebug
./FFTools/mkupdate/mkupdate.sh -l rk3399_roc_pc_plus-userdebug
```

### 三、 运行时验证与注意事项

#### 1. 刷机验证时必须“擦除用户数据”
*   **现象**：烧录了新固件后，发现桌面上依然存在已被删除的“可卸载预装应用”。
*   **原因**：可卸载的预装应用（`preinstall_del`）是在系统**首次开机**时，由系统脚本自动拷贝并安装到 `/data/app/`（用户数据分区）下的。如果您在烧录新固件时，没有勾选“擦除用户数据（Wipe Userdata）”，或者使用的是增量刷写，设备上原有的用户数据分区依然保留着该 App 的安装残留。
*   **正确做法**：在新固件烧录完成后，必须在烧录工具中**执行完全擦除（Wipe Data）**，或者在设备上手动进行一次**恢复出厂设置**，再次开机后，该 App 才会彻底消失。

#### 2. 在线快速验证（免刷机）
在开发调试阶段，如果想立即在板子上验证删除效果，无需重新刷机，可直接使用 adb 提权清理设备端对应的路径：
```bash
# 1. 提权并解锁分区
adb root
adb remount

# 2. 清理系统端或 OEM 端预置的 APK 包
adb shell rm -rf /system/app/MyTestApp/
adb shell rm -rf /oem/app/MyTestApp/

# 3. 卸载设备上已安装的用户端 App
adb shell pm uninstall com.example.mytestapp
```
